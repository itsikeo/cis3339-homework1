# CIS 3339 Homework 1 — Student Management System

Vue 3 Composition API migration of the supplied HTML/JavaScript starter. Express serves the production application and REST API; MongoDB replaces JSON storage. The original sample record is intentionally not imported: the grader can start with an empty database.

## Requirements and setup

- Node.js 22 recommended, npm, modern browser.
- MongoDB Community Edition installed locally (no Atlas, credentials or replica set required).
- Start MongoDB: macOS with Homebrew `brew services start mongodb-community` (or the installed versioned formula, e.g. `mongodb-community@8.0`); Windows administrator terminal `net start MongoDB` or Services; Linux `sudo systemctl start mongod`. Installation reference: https://www.mongodb.com/docs/manual/installation/.

Open the project root (the directory containing package.json and .env) and run:

```bash
npm install
npm run build
npm start
```

Open **http://localhost:3000**. The included real `.env` contains:

```dotenv
MONGODB_URI=mongodb://127.0.0.1:27017/cis3339_homework1
PORT=3000
```

No manual database creation, seed, migration or import needed. Mongoose creates collections and indexes on startup. For development, start the backend with `npm start` and run `npm run dev` in a second terminal; Vite proxies API requests to port 3000. Production refreshes at `/students`, `/courses`, `/enrollments` use Express's SPA fallback.

## Architecture and features

Vue Router provides three views. Pinia shares student and course lists. Composition API handles reactive forms, computed search results, lifecycle, and loading/error/success states. Reusable table and feedback components provide consistent responsive UI. Express validates requests and Mongoose models students, courses, and enrollments. Enrollment references use MongoDB ObjectIds; unique indexes reject duplicate IDs and student/course pairs. Writes are serialized within the single server to avoid concurrent deletion/enrollment races. Parent deletion removes enrollments first; standalone MongoDB does not provide multi-document atomicity, so an interrupted deletion may leave the parent with its enrollments removed. The old JSON database and legacy scripts are removed.

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/api/students?q=John` | List/search students (optional q) |
| POST | `/api/students` | Create `{name,id,phone,zip}` |
| DELETE | `/api/students/:id` | Delete student and enrollments |
| GET | `/api/courses` | List courses |
| POST | `/api/courses` | Create `{id,name}` |
| DELETE | `/api/courses/:id` | Delete course and enrollments |
| POST | `/api/enrollments` | Create `{studentId,courseId}` |
| GET | `/api/courses/:id/students` | Course roster |

IDs are strings; URL-encode IDs in paths. Status codes: 200 successful read/delete; 201 creation; 400 invalid input; 404 missing record; 409 duplicate; 500 unexpected server error.

## Tests before submission

With local MongoDB running and dependencies installed, run `npm test`. The integration test uses a uniquely named temporary database, checks empty startup, CRUD, search, duplicate prevention, missing references, rosters, reconnect persistence and cascading deletes, and drops only its own test database.

Manual production testing:

1. Run the production commands above and open localhost:3000.
2. Add John / 1001 / 555-1234 / 77001 and Jane / 1002 / 555-5678 / 77002. Search John; try duplicate 1001.
3. Add CIS 3339 / Enterprise Applications Development and CIS 3368 / Advanced Object-Oriented Programming. Try adding duplicate course ID.
4. Enroll both students in CIS 3339; verify both appear in the roster. Attempt duplicate enrollment.
5. Stop/restart server; verify persistence. Inspect MongoDB using Compass or mongosh.
6. Delete John; verify only Jane remains in the roster. Delete CIS 3339; verify related enrollments are removed.
7. Refresh each route; verify mobile layout, validation, empty states and browser/server logs.
8. Verify fresh local MongoDB startup without manual preparation.
